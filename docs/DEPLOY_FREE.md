# 🆓 Zero-cost deployment — Vercel (web + proxy) + Render (API) + Neon (DB)

The exact, $0, **no-custom-domain**, **no-auth-code-change** runbook. It works because the web app
**proxies `/api/*` to the API** (`apps/web/next.config.mjs` → `rewrites()`), so the browser only talks
to the Vercel origin and the `SameSite=Strict` refresh cookie stays first-party (login + refresh +
reload all work — even in Safari).

```
Browser ──https──▶ app.vercel.app ──(server-side rewrite)──▶ stockeasy-api.onrender.com ──▶ Neon
          (cookie is first-party to vercel.app → SameSite=Strict OK)
```

## Prerequisites
- GitHub account; the repo pushed to GitHub (Step 0).
- Free accounts: **Neon**, **Render**, **Vercel**, **UptimeRobot**.

## Step 0 — push to GitHub
From the repo root (the agent already ran `git init` + the first commit; if not, do it):
```bash
git init -b main
git add -A
git commit -m "Stock Easy"
# Create an EMPTY repo on github.com (no README), then:
git remote add origin https://github.com/<you>/stock-easy.git
git push -u origin main
```
> ✅ The root `.gitignore` keeps `node_modules/`, `.next/`, `dist/`, and **all `.env` files** out of
> the commit. Confirm with `git ls-files | grep -i env` → you should see only `*.env.example`.

## Step 1 — Database (Neon, free)
1. neon.tech → **New Project** (pick a region near your API region).
2. Copy the **direct** (non-pooled) connection string and append `?sslmode=require` — you'll set it as **both** `DATABASE_URL` and `DIRECT_URL` (the schema declares `directUrl`, so the Prisma CLI requires `DIRECT_URL`):
   ```
   postgresql://USER:PASSWORD@ep-xxxx.REGION.aws.neon.tech/neondb?sslmode=require
   ```

## Step 2 — API (Render, free)
1. Render → **New → Blueprint** → select this repo → **Apply** (it reads `render.yaml`).
   *(Or New → Web Service, Root Directory `apps/api`, build/start as in `render.yaml`.)*
2. Set the dashboard env vars (the Blueprint marks these `sync:false`):
   - `DATABASE_URL` = the Neon string from Step 1
   - `DIRECT_URL` = the **same** Neon string (required by the schema's `directUrl`; non-pooled DB → same value as `DATABASE_URL`). Without it the build's `prisma migrate deploy` fails with **P1012**.
   - `CORS_ORIGIN` = a placeholder for now (e.g. `https://example.vercel.app`) — fixed in Step 4
   - `GEMINI_API_KEY` = your **rotated** Gemini key (optional; `/ai` returns 503 without it)
   - `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` are auto-generated by the Blueprint.
3. Deploy → wait for green → **copy the API URL**, e.g. `https://stockeasy-api.onrender.com`.
4. Verify: `curl https://stockeasy-api.onrender.com/health` → `{"success":true,"data":{"status":"ok"...}}`.

## Step 3 — Web (Vercel, free)
1. Vercel → **Add New → Project** → import the repo.
2. **⚠️ Root Directory = `apps/web`** (monorepo). Framework auto-detects Next.js.
3. Environment Variables (Production):
   - `API_PROXY_TARGET` = `https://stockeasy-api.onrender.com`  ← the Render URL (server-side; enables the proxy)
   - `NEXT_PUBLIC_API_URL` = `/api/v1`  ← relative → calls go same-origin through the proxy
   - `NEXT_PUBLIC_CURRENCY` = `₹` (optional)
4. Deploy → **copy the app URL**, e.g. `https://stockeasy.vercel.app`.

## Step 4 — close the loop (CORS)
1. Back in **Render**, set `CORS_ORIGIN` = your real Vercel URL (`https://stockeasy.vercel.app`) → save (redeploys).
2. *(Optional)* set the GitHub repo variable `API_HEALTH_URL = https://stockeasy-api.onrender.com/health`
   to enable the backup keep-warm workflow.

## Step 5 — migrate (and optionally seed) the database
Run locally against Neon (free hosts may not give you a shell). Prisma needs BOTH `DATABASE_URL` and
`DIRECT_URL` (the schema declares `directUrl`); for a non-pooled Neon DB set them to the same string:
```bash
cd apps/api
# bash:   export DATABASE_URL="postgresql://...sslmode=require"; export DIRECT_URL="$DATABASE_URL"
# pwsh:   $env:DATABASE_URL="postgresql://...sslmode=require"; $env:DIRECT_URL=$env:DATABASE_URL
npm run db:migrate          # prisma migrate deploy
npm run db:seed             # OPTIONAL — demo data (8 shops, 304 meds, 930 bills). Skip for a real DB.
```

## Step 6 — keep the free API warm (avoids cold-start + proxy 504)
UptimeRobot → **Add New Monitor** → HTTP(s) → `https://stockeasy-api.onrender.com/health` → interval **5 min**.
This keeps Render awake (within its free 750 instance-hours/month) **and** gives you uptime alerts.

## Step 7 — smoke test & validation
- `curl https://stockeasy-api.onrender.com/health` → 200
- Open `https://stockeasy.vercel.app` → sign in (`owner.apollo@stockeasy.test` / `StockEasy123!`)
- **Reload the page → you stay logged in** ← proves the proxy/cookie path works
- Wait > 15 min, click around → still authenticated (refresh works)
- DevTools → Network: requests go to `https://stockeasy.vercel.app/api/v1/*` (same-origin), no CORS errors

## Troubleshooting
- **Logged out on reload / after 15 min** → `API_PROXY_TARGET` not set (proxy off) or `NEXT_PUBLIC_API_URL`
  isn't `/api/v1`. The browser must call the Vercel origin, not Render directly.
- **First request hangs ~50s or 504** → Render cold start; set up the UptimeRobot keep-warm (Step 6).
- **CORS error in console** → `CORS_ORIGIN` on Render must equal the exact Vercel origin.
- **API exits on boot / "Invalid environment configuration"** → a required var missing; `JWT_*` must be ≥16 chars; `CORS_ORIGIN` must not be `*`.
- **`@prisma/client did not initialize`** → build must run `prisma generate` (the `render.yaml` build command does).
- **DB SSL error** → ensure `?sslmode=require` on `DATABASE_URL`.
